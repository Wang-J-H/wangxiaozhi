Langfuse 集成

为什么 Xiaozhi 需要 Langfuse

Langfuse 是一套面向大模型应用的可观测性平台，适合用来观察一次智能体执行过程中到底发生了什么。在 Xiaozhi 里，一轮用户消息通常不会只对应一次简单的模型调用，它往往会伴随 LangGraph 图执行、工具调用、知识库检索以及多轮中间状态切换。

Langfuse 的价值在于，它把这些原本分散的执行细节收拢到同一条 trace 里，让你能够从一次对话出发，回看模型输入输出、工具链路、耗时和错误位置。

在 Xiaozhi 中能做什么

Xiaozhi 对 Langfuse 的映射方式比较直接：

  • 一个 Xiaozhi 用户映射为 Langfuse 中的 user_id
  • 一个对话线程映射为 session_id
  • 每次用户输入触发的一轮智能体执行形成一条独立的 trace

当 Langfuse 与 Xiaozhi 连通之后，你可以看到：

  • 这一轮调用关联的是哪个用户、哪个线程、哪个智能体
  • 模型调用、工具调用和整体耗时表现
  • 用户反馈评分（点赞/点踩）会同步写入 Langfuse score

如何配置

启用 Langfuse 需要在运行 Xiaozhi 的环境中配置以下环境变量：

  • LANGFUSE_PUBLIC_KEY：用于鉴权
  • LANGFUSE_SECRET_KEY：用于鉴权
  • LANGFUSE_BASE_URL：指定 Langfuse 服务地址（官方云服务通常为 https://cloud.langfuse.com）

Langfuse 只有在 key 配置完整时才会被启用。如果没有配置上述变量，Xiaozhi 会自动退化为"不启用 tracing"的状态，正常聊天功能不会因此中断。

配置后系统会如何工作

理解 Langfuse 的关键点在于，它并不等于"所有调试信息都会立即显示在界面里"。当前 Xiaozhi 的设计重点是先把 trace id 与执行上下文稳定关联起来，再把这些信息作为后续调试和分析的基础。

系统会优先保证聊天主链路的稳定性，而不是为了获取额外的可点击 URL 去同步等待 Langfuse 的远程接口。也就是说，Langfuse 在 Xiaozhi 里首先是观测数据的来源，其次才是一个方便跳转查看的外部页面入口。

如何查看是否生效

启用完成后，最常见的查看方式是在 Langfuse 控制台中按项目查看 traces。进入项目后，可以按照用户、线程、Agent 或时间范围来筛选，定位到某一轮具体的请求。

快速确认是否生效的方法：发起一条真实对话，再到 Langfuse 控制台中按最近时间排序查看是否出现新的 trace。

当前建议的接入方式

目前 Xiaozhi 推荐的接入顺序是：

  1. 先完成 tracing，确保 trace 关联稳定
  2. 再使用反馈 score 分析用户满意度
  3. 后续再扩展到更完整的运营面板

只有在 trace 关联已经稳定、用户和线程维度映射已经一致的前提下，后续的评分、质量分析和使用统计才会真正可靠。
